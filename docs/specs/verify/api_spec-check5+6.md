# Bảng tổng hợp nhận xét và đề xuất chỉnh sửa Database

Bảng dưới đây đối chiếu yêu cầu của Frontend (FE) với cấu trúc hiện tại trong file database.txt, kèm theo đề xuất thay đổi cụ thể (DBML).

| Module        | API Route             | Trường dữ liệu FE cần                                     | Tình trạng trong database.txt                             | Nhận xét & Đề xuất chỉnh sửa (DBML)                                                                                           |
| ------------- | --------------------- | --------------------------------------------------------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **Interview** | `GET /sessions`       | `status` (ACTIVE/COMPLETED)                               | Đang là `status boolean` trong `interview_session`.       | **Đề xuất:** Tạo `enum SessionStatus { ACTIVE, COMPLETED }` và đổi kiểu dữ liệu cột `status` thành `SessionStatus`.           |
| **Interview** | `GET /sessions`       | `score`                                                   | Nằm ở cột `overall_score` trong bảng `interview_reports`. | **Nhận xét:** BE cần JOIN bảng `interview_session` và `interview_reports` qua `session_id` để lấy điểm trả về.                |
| **Interview** | `GET /.../report`     | `overall_score`, `strengths`, `weaknesses`, `suggestions` | Có đầy đủ các cột tương ứng trong `interview_reports`.    | **Nhận xét:** Khi gen report, BE phải cập nhật cột `ended_at` trong `interview_session` và đổi `status` thành `COMPLETED`.    |
| **Payment**   | `POST /payos/create`  | `expires_at`                                              | Không có trong bảng `transaction`.                        | **Đề xuất:** Thêm cột `expires_at datetime` vào bảng `transaction` để FE hiển thị countdown và BE chạy Cronjob hủy giao dịch. |
| **Payment**   | `GET /.../status`     | `completed_at`                                            | Không có trong bảng `transaction`.                        | **Đề xuất:** Thêm cột `completed_at datetime` vào bảng `transaction` để ghi nhận thời điểm thanh toán thành công.             |
| **Payment**   | `POST /payos-webhook` | Xử lý logic nội bộ                                        | Các bảng `transaction` và `enrollment` đã có sẵn.         | **Nhận xét:** Khi webhook báo thành công, BE cập nhật `transaction` và tự động INSERT vào `enrollment` để cấp quyền học.      |

# Format lại API Route theo đề xuất chỉnh sửa

### 5. AI Mock Interview Module (`/api/interviews`)

- **`GET /api/interviews/sessions`**
- _Description_: List past interview sessions of the student.
- _Response_: Session array (`id`, `topic`, `level`, `started_at`, `status` `ACTIVE/COMPLETED` _(mapped từ enum SessionStatus mới)_, `score` _(lấy từ interview_reports.overall_score)_).

- **`POST /api/interviews/sessions`**
- _Description_: Initialize a new Mock Interview session. Fetches the opening question from Gemini.
- _Request Body_: `topic`, `level` (`INTERN`, `FRESHER`, `JUNIOR`, `SENIOR`).
- _Response_: `session_id`, `first_question`.

- **`POST /api/interviews/sessions/{sessionId}/chat`**
- _Description_: Post candidate answer. System stores messages in `interview_message` and streams the next AI response via SSE.

- _Request Body_: `message`.
- _Response Stream (SSE)_: Stream of text chunks containing the AI's follow-up question.

- **`GET /api/interviews/sessions/{sessionId}/report`**
- _Description_: Retrieve evaluation score report card. Calling this or completing the session triggers BE to update `ended_at` and set `status` to `COMPLETED` in `interview_session`.
- _Response_: `overall_score` (radial scale 1-10), `strengths` (List of points), `weaknesses` (List of points), `suggestions`, `chat_transcript` (messages array from `interview_message`).

### 6. PayOS Payments (`/api/payments`)

- **`POST /api/payments/payos/create`**
- _Description_: Initiate a checkout session. Generates PayOS VietQR payment details and creates a `PENDING` record in the `transaction` table.
- _Request Body_: `course_id`.
- _Response_: `transaction_code`, `payos_link`, `qrcode` (VietQR image link generated by PayOS), `amount`, `expires_at` _(lưu trữ đồng bộ vào DB để đối chiếu)_.

- **`POST /api/payments/payos-webhook`**
- _Description_: Receive transaction verification hook from PayOS. Resolves concurrency using locking. If successful, updates `transaction.status` to `COMPLETE`, sets `completed_at`, and creates a new active record in `enrollment`.
- _Request Body_: Standard PayOS notification schema.
- _Response_: `{ "status": "ok" }`.

- **`GET /api/payments/transactions/{transactionCode}/status`**
- _Description_: Check if the transaction payment is successfully completed.
- _Response_: `status` (`PENDING`, `COMPLETE`, `FAILED`), `amount`, `completed_at` _(trích xuất từ cột mới thêm trong DB)_.
